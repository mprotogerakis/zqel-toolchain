# Was die MinGW-Baumaschine fuer unsere Windows-Werkzeugpakete braucht
# (eine Zeile je pacman-Paket).
#
# Warum es diese Datei gibt und nicht deps.winget.json:
# winget kennt keine Compiler-Bibliotheken. MSYS2 SELBST steht im
# winget-Manifest - was darin installiert wird, steht hier. Zwei Systeme,
# aber je eine Liste; keine Liste steht zweimal.
#
# Warum EINE Liste fuer alle Werkzeuge: sie beschreibt die Maschine, nicht ein
# Werkzeug. Eine Liste je Paket haette dieselben vier Zeilen mehrfach gefuehrt.
# Wer was braucht, steht in den Kommentaren.
#
# Was NICHT hier steht: die gebauten Werkzeuge selbst. Ihre Quellen sind in
# gappa-pin.json und matiec-pin.json per Hash bzw. Revision festgelegt.
#
# Gemessen am 2026-09-13: MSYS2 kennt 15725 Pakete und weder gappa noch matiec
# darunter (Gegenprobe: `boost` trifft achtmal). Selbst bauen war auf dieser
# Plattform also kein Abwaegen zwischen zwei Quellen, sondern der einzige Weg.

# beide
mingw-w64-x86_64-gcc
make

# gappa: Boost fuer den Parser, GMP und MPFR fuer die Intervallarithmetik
mingw-w64-x86_64-boost
mingw-w64-x86_64-gmp
mingw-w64-x86_64-mpfr

# matiec: liefert kein fertiges `configure` mit - es gibt keine Releases, nur
# den Baum. Deshalb muss `autoreconf -i` zuerst laufen.
autoconf
automake
flex
bison
