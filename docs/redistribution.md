# What we redistribute, and under which terms

Generated by `tools/redistribution_report.py` from the pin files the
build and the mirror actually use. Editing this page by hand would make
it a second, drifting claim; change the pins instead.

This is **not legal advice**. It is the dossier for a licence review:
every artifact we publish, what its licence asks of a distributor, and
what we do about it. What it does *not* cover is listed at the end.

---

## 1. Software we build ourselves

We compile these from pinned sources and publish the result. That makes
us a distributor of the compiled work *and* of the libraries it links.

### Gappa 1.4.0 (Windows x86_64)

- **Licence:** CECILL-2.1 AND GPL-3.0-or-later
- **Source:** https://gappa.gitlabpages.inria.fr/releases/gappa-1.4.0.tar.gz
  (sha256 `6bf17688f0d0d0815713f3c3ad567747…`)
- **Upstream:** https://gitlab.inria.fr/gappa/gappa
- **Linked dynamically**, libraries shipped beside the binary:

  | Library | From | Licence |
  |---|---|---|
  | `libgcc_s_seh-1.dll` | mingw-w64-x86_64-gcc-libs | spdx:GPL-3.0-or-later WITH GCC-exception-3.1 AND LGPL-2.1-or-later |
  | `libgmp-10.dll` | mingw-w64-x86_64-gmp | LGPL3  GPL |
  | `libmpfr-6.dll` | mingw-w64-x86_64-mpfr | spdx:LGPL-3.0-or-later |
  | `libstdc++-6.dll` | mingw-w64-x86_64-gcc-libs | spdx:GPL-3.0-or-later WITH GCC-exception-3.1 AND LGPL-2.1-or-later |
  | `libwinpthread-1.dll` | mingw-w64-x86_64-libwinpthread | spdx:MIT AND BSD-3-Clause-Clear |

- **How the obligations are discharged:**
    - full licence texts inside the package, under `licenses/`;
    - `NOTICE.txt` naming every bundled library and its licence;
    - `SOURCES.txt` naming where each compiled source came from;
    - the source archive published in the same directory as the binary;
    - dynamic linking, so an LGPL library can be replaced in place.

  Why dynamic: GMP und MPFR stehen unter LGPLv3. Statisch gelinkt laeuft gappa.exe zwar allein (gemessen: 21434128 Bytes, keine fremde DLL), verpflichtet uns aber, eine Relink-Moeglichkeit beizulegen. Dynamisch plus die fuenf DLLs ist der lizenzsaubere Weg und der, den das Paket geht.

### zqel itself

The standalone builds embed a Python runtime, the packages Nuitka
reports as included, and Z3's native library. The package carries a
`NOTICE.txt` generated from Nuitka's own report and from the licence
metadata each package publishes — not from a hand-kept list. Licence
texts land under `licenses/`.

## 2. Software we mirror unchanged

Byte-for-byte copies of upstream releases. We do not repack them:
repacking would turn passing something on into modifying it, and
different obligations would apply. Each copy has a `.notice.txt` beside
it naming origin, checksum and licence.

## 3. What this dossier does not cover

- **The transitive dependency closure of the Windows build machine.**
  `tools/windows/msys2.lock.json` pins the packages we install and the
  owners of the DLLs we ship. Everything those pull in is not pinned.
- **A legal reading.** Nobody with a licence qualification has looked at
  this. The obligations above are what the licence texts say, read by an
  engineer.
- **cvc5's exact binary configuration.** We mirror the release variant
  without `-gpl` in its name. Whether that build links GMP statically,
  and what that means for the LGPL relink provision, has not been
  established by inspecting the binary.
- **Anything distributed outside `dl.zqel.org` and the forgejo package
  registry.**
